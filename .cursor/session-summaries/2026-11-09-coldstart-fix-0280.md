# 0.2.80: an open chat no longer stays empty after an offline cold start

**Date:** 2026-11-09 · **Version:** 0.2.80 (`d0c3f91a`) · **Tiers deployed:** web, APK (20080); backend redeployed by the APK switch (no backend code change)

## What was done
- 11-08 Android drive of 0.2.79 showed "Brak wiadomości" in an open chat after an offline cold start. Differential on Pixel_7 (published 0.2.76 APK, then in-place 0.2.79): identical on both, so PRE-EXISTING. Worse than first reported: the chat stayed empty after the network returned until a lifecycle resume (a notification-permission prompt at reconnect hid it).
- Cause: `EncryptionService.allLocalMessageRecords` returns `{}` while `_userId` is null (`encryption_service.dart:3966-3968`); `_userId` is set only by `initializeE2E` at socket connect; nothing re-read the open chat on E2E-ready.
- Fix (PR #229, owner "Fix now"): `MessagingProvider.rereadOpenChat()` (`messaging_provider.history.dart`) re-runs the open chat's local merge from the `onE2EReady` hook (`connection_provider.dart`); rows held stay, no scroll/pagination reset, no second mark-read. List previews already recovered there (now pinned by a test).
- Trap recorded (PR #228), marked FIXED in 0.2.80; `wire.md` one bullet, `e2e-invariants.md` line 121.

- Follow-up the same day: the web 0.2.80 publish went out WITHOUT the Giphy key (`-VmSshTarget` from a worktree with no `deploy-web.config.ps1`); re-published 09:18Z and `deploy-web.ps1` now refuses that (PR #231) — see `2026-11-09-gif-key-deploy-gate.md`.
