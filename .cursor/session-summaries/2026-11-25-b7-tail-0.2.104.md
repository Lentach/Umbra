# 0.2.104 released: the server refuses a plaintext recovery phrase; legacy-key accounts get a dialog; first APK through the CI path

**Date:** 2026-11-25 · **Version:** 0.2.104 · **Tiers deployed:** backend, web, APK

## What was done
- Owner decisions (form, 2026-11-25): plaintext phrase refused in 0.2.104; a dialog on app open, once per app start. Measured on prod before: 7 `phrase_v1` rows (6 with a v1 backup, 1 linked account), 4 active in 5 days, none replaced since 0.2.90; a current app already could not recover a password with such a key.
- PR #304 (backend): `setRecoveryKey`, the identity-reset request and `POST /auth/recover` refuse the legacy plaintext field; nothing is verified, stored, counted or logged; the reset door keeps `existing` / `not_enrolled` / `cooldown` first. The `phrase` credential kind and the unreachable no-backup enrolment branch are removed. No entity or SQL change; the 7 rows stay as markers.
- PR #305 (frontend): dialog on the chat list (`widgets/dialogs/legacy_recovery_key_dialog.dart`), once per app start per account, "Wymień teraz" / "Później"; waits for the device-link gate, the passcode lock, another tab or a pushed screen and retries (`appRouteObserver`, `ConversationsScreen.visible`); the contact-backup sheet is deferred behind it, not dropped. Version 0.2.104.
- Release through the new APK path: tag `v0.2.104` → `release-apk.yml` built and published the unsigned APK → `sign-ci-apk.ps1 -Tag v0.2.104 -PublishChecksum` signed it. First public GitHub release.
- PR #306 (OPEN, needs the owner's word): the `-Tag` provenance check failed closed on its first run (`gh --jq` lost its double quotes under Windows PowerShell). Fixed by parsing the release JSON in PowerShell; the release was signed with that fixed script from the working tree, then the tree was restored.
- Out of repo: prod `.env` `ANDROID_APK_*` → 20104 / 0.2.104 (backup `.env.bak.pre-apk-0.2.104`).
