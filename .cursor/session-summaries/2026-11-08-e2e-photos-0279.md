# 0.2.79: profile photos end-to-end over the box (decision 138, release A); build-cache auto-prune; disk cleanup

**Date:** 2026-11-08 · **Version:** 0.2.79 (`40089998`) · **Tiers deployed:** backend, web, APK (20079)

## What was done
- Disk (owner): VM `docker builder prune` 9.66 GB + `journalctl --vacuum-size=500M` 2.0 GB → 32 %. `deploy-backend.sh` now prunes build cache older than 72 h after a healthy deploy (PR #225; ran on both deploys today). Declined for now: disk alarm >80 %, journald cap, 7-day local backups (NEXT.md).
- Decision 138 (owner): R84's "avatar signed URLs" replaced. Signed or login-gated fetches would show the server who views whom; instead one photo per account goes E2E as box media, referenced by a quiet `profile` frame (`av {m,k,i,r}`) to friend devices and siblings and in request/accept; re-sent weekly; `searchUsers` returns no photo; upload/gallery routes removed. Plan: `docs/plans/2026-11-08-e2e-profile-photos.md`.
- Rev rules (after review): a user change takes `max(last+1, now ms)`; a weekly refresh `held.rev + 1`, committed only if the held reference is unchanged; migration `r = 1`; one queue for all own-photo work; a restore applies the backup's own reference when it outranks; remove-before-migration writes a cleared reference; a friend reference naming a held media id is refused.
- Server: `searchUsers` without photo fields, `UserMapper` deleted; `POST /users/profile-picture` + `/users/profile-photos/*` removed; `multer` dropped (override pinned literally `^2.3.0`). `/users/me` `profilePictureUrl` and `GET /media/avatars/*` stay for the migration window.
- Built by subagents (server, client, two drives, Android); reviewer found 2 P1 + 2 P2, all fixed red-first; the drive agent caught the `$multer` override breaking `npm ci`.
- PR #226 merged as `40089998`.
