# Metadata privacy Phase 2 finished: server-held contact backup (PR2.4) + user-held history backup (PR2.3), proven on a wiped device

**Date:** 2026-09-20 · **Version:** unchanged (0.2.51 backend / 0.2.50 web on prod; branch only) · **Tiers deployed:** none

## What was done
- `backend/src/backup/` + migration `0021`: `GET/PUT /backup/contacts` (JWT, 30/min), one opaque `contact_backups` row per account, FK `ON DELETE CASCADE`. Wire carries **`rev`** — optimistic concurrency over the WHOLE triple `(ckId, wraps, blob)`, added beyond the plan because atomicity alone does not stop a new blob landing beside another device's stale wraps (= a row nobody can open). Salt immutable (`409 salt_mismatch`); **a no-op PUT moves neither `rev` nor `updatedAt`** (the `key_bundles.updatedAt` presence-clock lesson). `main.ts` body limit 100 kb → 4 mb.
- `contacts/contact_backup.dart` + `contact_backup_service.dart`: blob = the device-independent half of each `_contact_v1_` record (`ContactRecord.toBackupJson()`, no `queues`/`legacy`) under a random CK; CK wrapped under PBKDF2-600k(password) and, once enrolled, (phrase). CK itself — not the derived key — cached as `<uid>.<ckId>.<b64ck>` in `AuthTokenStore`, so a password change re-makes only the WRAP and a cached CK matching `ckId` costs ZERO PBKDF2 on an ordinary login.
- `AuthProvider` owns the service (a credential call is the only moment the password exists): `_adoptSession(password:, phrase:)` resolves unawaited; `resetPassword` uploads the new wrap ADDITIVELY **before** the change revokes every token; logout clears CK with the session.
- `ConnectionProvider.connect()` step 4c restores BEFORE the socket, waiting (`kContactBackupRestoreBudget`, 8 s) **only when the local store came up empty**. `ContactStore.onChanged` (fires only on a real disk change) drives a debounced upload — change-driven, so a store that failed to open can never publish an empty graph.
- `services/backup/`: `HistoryBackupCodec` (PBKDF2-600k, fresh salt, AES-GCM, injectable seams, `WrongPassphrase`/`Corrupt`/`ForeignAccount`), `history_backup_service.dart` (export all platforms via `share_plus` 12.0.2 / browser download; import native-only, upgrade-only), `storage_loss.dart`, `backup_file_out_{io,stub}.dart`.
- UI: Privacy & Safety backup card (export + import, import absent on web), `backup_passphrase_dialog.dart`, `storage_loss_screen.dart` mounted in `PasscodeGate._body`'s Stack BELOW the lock layers. 32 new l10n keys in both arbs.
- Two defects found by their own proofs and fixed: `deriveWrapKey` let a refused primitive escape as an **unhandled async error** through the unawaited login call (turned `auth_token_fault_injection` e2e red; now every KDF failure is `ContactBackupCorrupt('kdf')` and `onSession` is genuinely non-throwing); and the loss-screen mount read a plain static, registering no dependency on a `const` widget, so the screen **could never have appeared** (`StorageLoss.listenable` is a `ValueNotifier`).
